# 🔍 Clean IP Scanner

<div dir="rtl">

ابزار پیدا کردن IP‌های تمیز CDN‌های مختلف برای Termux (اندروید ARM64)

---

## ✨ ویژگی‌ها

- اسکن هزاران تا ده‌ها میلیون IP از رنج‌های CDN‌های مختلف — نه فقط Cloudflare
- **پشتیبانی از تمام CDN‌های بزرگ دنیا:**
  - **Cloudflare** — پیش‌فرض ابزار
  - **Akamai** — یکی از بزرگ‌ترین CDN‌های جهان
  - **Fastly** — CDN محبوب برای سرویس‌های بزرگ
  - **Amazon CloudFront** — CDN آمازون
  - **Microsoft Azure CDN**
  - **Google Cloud CDN**
  - **BunnyCDN**
  - **KeyCDN**
  - **Limelight Networks**
  - و هر CDN دیگری که رنج IP‌های آن در دسترس باشد
- **دو روش اسکن پیشرفته:**
  - **حالت Normal:** تست TCPing (۴ بار) + تست سرعت دانلود و آپلود واقعی
  - **حالت Xray:** اسکن واقعی از طریق هسته‌ی Xray با کانفیگ شخصی شما
- **تست سرعت دانلود و آپلود واقعی:** هر IP کاندید هم از نظر سرعت دانلود و هم سرعت آپلود واقعی تست می‌شود (نه تخمینی) و در نهایت IP‌ها بر اساس مجموع بهترین سرعت دانلود و آپلود مرتب می‌شوند — این قابلیت در هر دو حالت Normal و Xray فعال است
- **انتخاب یک یا چند پورت اسکن (تا ۱۳ پورت همزمان):** کاربر می‌تواند یک پورت دلخواه (۱ تا ۶۵۵۳۵) یا حداکثر ۱۳ پورت را با جداکننده‌ی کاما وارد کند (مثلاً `443,8443,2053,2083,2087,2096,80,8080,8880,2052,2082,2086,2095`)؛ هر IP روی تمام پورت‌های واردشده تست می‌شود و در خروجی (جدول ترمینال و هر دو فایل txt) مشخص است که هر IP روی کدام پورت سالم بوده؛ اگر Enter بزند پورت پیش‌فرض ۴۴۳ استفاده می‌شود — این قابلیت در هر دو حالت Normal و Xray فعال است
- **پشتیبانی از IPv4 و IPv6** — رنج‌های IPv6 با subnet کوچک در فایل `ip_ranges.txt` قابل استفاده‌اند
- **حفاظت در برابر رنج‌های غیرعملی:** اگر یک رنج CIDR (در یک خط) بیش از ۵ میلیون آدرس داشته باشد، به جای crash، پیام خطای راهنما نمایش داده می‌شود و از آن رنج رد می‌شود — بقیه‌ی رنج‌ها به‌طور عادی اسکن می‌شوند
- **مصرف RAM بهینه‌شده:** هر IP تنها ۱۶ بایت فضا می‌گیرد. برای ۳۰ میلیون IP تنها ~۴۸۰ مگابایت RAM نیاز است
- **تعداد worker قابل تنظیم در حالت Xray:** عددی بین ۱ تا ۱۶ را بر اساس قدرت دستگاه خود انتخاب کنید
- **ذخیره و ادامه‌ی اسکن:** پیشرفت اسکن به‌صورت خودکار ذخیره می‌شود (در حالت Normal هر ۲۰۰۰ IP، در حالت Xray هر ۵۰۰ IP)
- **پشتیبانی از لیست‌های بسیار بزرگ:** امکان اسکن ده‌ها میلیون IP در چند نوبت
- **پشتیبانی از دو فرمت کانفیگ برای حالت Xray:**
  - **URL** (فایل `config/xray_config.txt`): لینک مستقیم کانفیگ
  - **JSON** (فایل `config/xray_config.json`): کانفیگ کامل Xray
- **ورود و ویرایش تعاملی کانفیگ Xray:** با انتخاب حالت Xray، کانفیگ خود (لینک URL یا JSON چندخطی) را مستقیماً در ترمینال Termux وارد کنید؛ ابزار آن را بررسی می‌کند و فقط در صورت معتبر بودن، در فایل مناسب ذخیره می‌کند. دفعه‌ی بعد کانفیگ ذخیره‌شده را خودکار تشخیص می‌دهد و فقط می‌پرسد می‌خواهید آن را ویرایش کنید یا از همان استفاده شود — ویرایش دستی فایل‌ها نیز همچنان ممکن است
- پشتیبانی از پروتکل‌های **VLESS، VMess، Trojan و Shadowsocks**
- محاسبه‌ی **نرخ Packet Loss** و **میانگین تأخیر** برای هر IP
- قابلیت توقف اسکن در هر لحظه با **Ctrl+C** و نمایش نتایج یافت‌شده تا آن لحظه
- نمایش **مدت زمان اسکن** در پایان
- ذخیره‌ی خودکار نتایج در فایل `clean_ips.txt` و لیست ساده در `clean_ips_list.txt`
- **کپی خودکار نتایج در پوشه‌ی Downloads اندروید:** پس از هر اسکن (حتی اسکنی که با Ctrl+C متوقف شده باشد)، هر دو فایل نتایج به‌طور خودکار در `~/storage/downloads/` کپی می‌شوند تا بدون هیچ دستور اضافه‌ای از برنامه‌ی Files اندروید یا هر برنامه‌ی دیگری در دسترس باشند. دفعه‌ی اول، اندروید یک‌بار اجازه‌ی دسترسی به حافظه را از شما می‌پرسد

## 📥 نصب

### روش اول: دانلود مستقیم فایل آماده (پیشنهادی برای اکثر کاربران)

این روش سریع‌ترین و ساده‌ترین روش است. فقط یک دستور در Termux وارد کنید:

```bash
pkg update && pkg upgrade -y && pkg install -y wget unzip && wget https://github.com/4n0nymou3/Clean-IP-Scanner/releases/latest/download/clean-ip-scanner-arm64.zip && unzip clean-ip-scanner-arm64.zip && chmod +x clean-ip-scanner
```

پس از اتمام، ابزار را اجرا کنید:

```bash
./clean-ip-scanner
```

**مزایا:**
- بسیار سریع (حدود ۳۰ ثانیه)
- بدون نیاز به نصب Go
- فایل آماده و کامپایل‌شده

**نکته:** فایل‌های کانفیگ و نتایج در همان پوشه‌ای که دستور را اجرا کردید ذخیره می‌شوند (معمولاً پوشه‌ی home یعنی `~`).

### روش دوم: ساخت از سورس کد

این روش برای کاربرانی است که می‌خواهند ابزار را مستقیماً از سورس کد در دستگاه خودشان بسازند. یک دستور ساده:

```bash
curl -sL https://raw.githubusercontent.com/4n0nymou3/Clean-IP-Scanner/main/install.sh | bash
```

پس از اتمام، از هرجایی در Termux اجرا کنید:

```bash
clean-ip-scanner
```

**مزایا:**
- ۱۰۰٪ سازگار با دستگاه شما
- ساخت مستقیم در Termux
- نصب خودکار در PATH (از هر پوشه‌ای قابل اجراست)
- دریافت خودکار هسته‌ی Xray

**معایب:**
- زمان بیشتر (تا ۱۰ دقیقه)
- نیاز به نصب Golang (به‌صورت خودکار انجام می‌گیرد)

**محل نصب و فایل‌ها:**
```
~/Clean-IP-Scanner/          ← پوشه‌ی اصلی برنامه
~/Clean-IP-Scanner/config/   ← پوشه‌ی فایل‌های کانفیگ
~/Clean-IP-Scanner/xray/     ← هسته‌ی Xray
```

## ▶️ اجرا و استفاده

### اجرای ابزار

**روش اول (دانلود مستقیم):**
```bash
./clean-ip-scanner
```

**روش دوم (ساخت از سورس):**
```bash
clean-ip-scanner
```

### انتخاب حالت اسکن

پس از اجرا، اگر اسکن ناتمامی وجود داشته باشد ابتدا این پیام نمایش داده می‌شود:

```
+-------------------------------------------------+
|         UNFINISHED SCAN DETECTED                |
+-------------------------------------------------+

  Previous scan mode : Xray (8 workers)
  Progress           : 1200 / 5956 IPs (20%)
  Responsive IPs     : 47 found so far
  Saved at           : 2025-01-15 22:30:14

Enter R to resume previous scan or N to start a new scan:
```

- **R** → ادامه‌ی اسکن قبلی از همان‌جایی که متوقف شده بود (پورت انتخابی قبلی نیز بازیابی می‌شود)
- **N** → شروع اسکن جدید (اسکن قبلی پاک می‌شود)

اگر اسکن ناتمامی وجود نداشته باشد، مستقیماً منوی زیر نمایش داده می‌شود:

```
Select scan mode:
  [1] Normal scan (TCP ping + speed test)
  [2] Xray scan (uses Xray core with your config)
Enter 1 or 2:
```

- **گزینه ۱ — Normal:** اسکن معمولی. بدون نیاز به هیچ تنظیمی.
- **گزینه ۲ — Xray:** اسکن با هسته‌ی واقعی Xray. نیازمند تعریف کانفیگ شخصی است.

### وارد کردن کانفیگ Xray (فقط در حالت Xray)

بعد از انتخاب گزینه ۲، ابزار بررسی می‌کند که کانفیگ معتبر Xray وجود دارد یا نه.

**اگر هنوز کانفیگی ذخیره نکرده‌اید**، این پیام و منو نمایش داده می‌شود:

```
No valid Xray configuration was found.
An Xray configuration must be provided first.
It will be saved automatically and reused in future scans.

Select the format of your Xray configuration:
  [1] URL configuration
  [2] JSON configuration
Enter 1 or 2:
```

- **گزینه ۱ — URL:** لینک کامل کانفیگ (`vless://` یا `vmess://` یا `trojan://` یا `ss://`) را کپی کنید، در ترمینال Paste کنید و Enter بزنید
- **گزینه ۲ — JSON:** کانفیگ کامل JSON را (حتی اگر چندخطی باشد) در ترمینال Paste کنید؛ سپس در یک خط جداگانه عبارت `END` را تایپ کنید و Enter بزنید
- با تایپ `BACK` (در ورودی URL، یا در خط اول ورودی JSON) به منوی انتخاب فرمت برمی‌گردید

ابزار کانفیگ را بررسی می‌کند. اگر نامعتبر یا ناقص باشد، دلیل آن نمایش داده می‌شود، **هیچ چیزی ذخیره نمی‌شود** و می‌توانید دوباره وارد کنید. اگر معتبر باشد، به‌صورت خودکار در `config/xray_config.txt` (برای URL) یا `config/xray_config.json` (برای JSON) ذخیره می‌شود و اسکن از همین کانفیگ استفاده می‌کند.

**اگر قبلاً کانفیگی ذخیره کرده‌اید** (حتی اگر آن را قبلاً به‌صورت دستی در فایل‌ها قرار داده باشید)، دوباره کانفیگ خواسته نمی‌شود و این منو نمایش داده می‌شود:

```
A previously saved Xray configuration was found (URL format).

Do you want to edit your existing Xray configuration?
  [1] Use existing configuration (default)
  [2] Edit configuration
Enter 1 or 2 (press Enter for default 1):
```

- **Enter یا ۱:** از همان کانفیگ ذخیره‌شده استفاده می‌شود
- **۲:** منوی انتخاب فرمت نمایش داده می‌شود و کانفیگ جدید را وارد می‌کنید

نکات مهم:
- این بررسی هنگام ادامه‌ی (Resume) یک اسکن ناتمام Xray هم انجام می‌شود
- در حالت Normal هیچ سؤالی درباره‌ی کانفیگ پرسیده نمی‌شود
- فرمتی که آخرین بار از طریق این منو ذخیره کرده‌اید، همان فرمتی است که اسکن از آن استفاده می‌کند؛ کانفیگ فرمت دیگر (در صورت وجود) حذف یا تغییر داده نمی‌شود
- ابزار محتوای کانفیگ شما (UUID، رمز عبور و...) را در ترمینال دوباره نمایش نمی‌دهد
- اگر کانفیگ JSON شما در یک خط بسیار طولانی (بیش از حدود ۴۰۰۰ کاراکتر) باشد، ممکن است ترمینال آن را کوتاه کند؛ در این صورت آن را چندخطی کنید یا فایل را به‌صورت دستی ویرایش کنید

### انتخاب تعداد worker (فقط در حالت Xray)

بعد از انتخاب گزینه ۲، این منو نمایش داده می‌شود:

```
Select number of parallel workers for Xray scan:
  4  - Recommended for weak/older devices
  8  - Recommended for most devices (default)
  16 - Recommended for powerful devices
  Valid range: 1 to 16
Enter worker count (press Enter for default 8):
```

عدد دلخواه را وارد کنید یا Enter بزنید تا پیش‌فرض ۸ استفاده شود. اگر عددی خارج از بازه ۱ تا ۱۶ وارد کنید، خطا نمایش داده می‌شود.

### انتخاب پورت اسکن

در آخرین مرحله، پیش از شروع اسکن، این منو نمایش داده می‌شود:

```
Enter scan port(s):
  Press Enter to use the default port (443)
  Or enter 1 to 13 ports (1-65535), separated by commas
  Example: 443,8443,2053
Port(s):
```

- **Enter (بدون وارد کردن عدد)** → پورت پیش‌فرض **۴۴۳** استفاده می‌شود
- **وارد کردن یک عدد** → ابزار روی همان پورت اسکن می‌کند
- **وارد کردن چند عدد (حداقل ۱ و حداکثر ۱۳ پورت)** → اعداد را با کاما از هم جدا کنید؛ ابزار هر IP را روی تمام آن پورت‌ها تست می‌کند

مثال برای پورت‌های TLS و غیر TLS کلادفلر:

```
443,8443,2053,2083,2087,2096,80,8080,8880,2052,2082,2086,2095
```

نکات مهم:
- پورت تکراری به‌طور خودکار حذف می‌شود، و اگر عدد نامعتبر یا بیش از ۱۳ پورت وارد کنید، ابزار خطا می‌دهد و دوباره می‌پرسد
- این قابلیت در **هر دو حالت Normal و Xray** کار می‌کند
- چون هر IP روی تمام پورت‌ها تست می‌شود، اسکن N پورت تقریباً N برابر زمان‌برتر از اسکن یک پورت است — برای اسکن اول روی رنج‌های بزرگ بهتر است از پورت‌های کمتری استفاده کنید
- اگر فقط یک پورت وارد کنید (یا Enter بزنید)، ابزار دقیقاً مثل قبل کار می‌کند و قالب خروجی تغییری نمی‌کند
- اگر اسکن قطع شود و دوباره ادامه دهید، تمام پورت‌های انتخابی قبلی به‌صورت خودکار بازیابی می‌شوند

## ⚙️ روند کار ابزار

### حالت Normal (گزینه ۱)

**مرحله ۱ — تست تأخیر (Latency):**
- تمام IP‌های موجود در فایل `config/ip_ranges.txt` تست می‌شوند
- هر IP دقیقاً ۴ بار از طریق TCP روی **پورت انتخابی شما** (پیش‌فرض: ۴۴۳) پینگ می‌شود — اگر چند پورت وارد کرده باشید، این کار برای هر IP روی تک‌تک پورت‌ها انجام می‌شود و هر ترکیب IP و پورت سالم جداگانه ثبت می‌شود
- نرخ Packet Loss و میانگین تأخیر برای هر IP محاسبه می‌شود
- نتایج بر اساس کمترین Packet Loss و سپس کمترین تأخیر مرتب می‌شوند

**مرحله ۲ — تست سرعت دانلود و آپلود:**
- از بین بهترین IP‌های مرحله‌ی اول، ۱۰ IP برتر تست دانلود و آپلود می‌شوند
- در اسکن چندپورتی، ابتدا از هر IP بهترین پورتی که با تست سرعت (HTTPS) سازگار است انتخاب می‌شود تا ۱۰ نتیجه از IP‌های مختلف به دست بیاید؛ پورت‌های غیر TLS کلادفلر (مثل ۸۰ و ۸۰۸۰) در صورت وجود پورت دیگر، در اولویت پایین‌تر قرار می‌گیرند
- تست دانلود و تست آپلود هر دو از سرورهای رسمی Cloudflare انجام می‌شوند (حجم تست دانلود: ۵۰ مگابایت، حجم تست آپلود: ۲۵ مگابایت)
- IP‌هایی که تست دانلود آن‌ها موفق نباشد، وارد تست آپلود نمی‌شوند

### حالت Xray (گزینه ۲)

**مرحله ۱ — تست تأخیر با هسته‌ی Xray:**
- برای هر IP، یک کانفیگ موقت ساخته می‌شود که IP اسکن‌شده جایگزین آدرس سرور در کانفیگ شما می‌شود و **پورت انتخابی شما** نیز اعمال می‌شود (در اسکن چندپورتی، برای هر ترکیب IP و پورت یک کانفیگ جداگانه ساخته می‌شود)
- هسته‌ی Xray با آن کانفیگ اجرا می‌شود و از طریق SOCKS داخلی، یک درخواست واقعی ارسال می‌شود
- اسکن با تعداد worker‌هایی که شما انتخاب کردید (۱ تا ۱۶) به‌صورت همزمان انجام می‌شود

**مرحله ۲ — تست سرعت دانلود و آپلود با هسته‌ی Xray:**
- از بین بهترین IP‌های مرحله‌ی اول، ۱۰ IP برتر انتخاب شده و سرعت دانلود و آپلود واقعی از طریق همان فرآیند Xray اندازه‌گیری می‌شود

### ذخیره‌ی خودکار پیشرفت

در حالت Normal، پیشرفت اسکن هر ۲۰۰۰ IP یک‌بار و در حالت Xray، هر ۵۰۰ IP یک‌بار در فایل `scan_checkpoint.json` ذخیره می‌شود. پورت (یا پورت‌های) انتخابی شما نیز در همین فایل ذخیره می‌شود. در اسکن چندپورتی، فاصله‌ی ذخیره‌سازی به نسبت تعداد پورت‌ها کمتر می‌شود تا حجم کار از دست‌رفته در صورت قطع ناگهانی کم بماند. اگر اسکن به هر دلیلی قطع شود (Ctrl+C، خاموش شدن دستگاه، بسته شدن Termux و...)، دفعه‌ی بعد که ابزار را اجرا کنید می‌توانید از همان‌جا ادامه دهید.

این قابلیت برای لیست‌های بسیار بزرگ هم کاملاً قابل اعتماد است — کاربر می‌تواند در طول چند روز و در چندین نوبت کل لیست را اسکن کند، بدون اینکه IP‌های قبلاً اسکن‌شده دوباره اسکن شوند.

### نتیجه‌ی نهایی (هر دو حالت)

IP‌ها بر اساس مجموع سرعت دانلود و آپلود (بالاترین مجموع در بالاترین رتبه) مرتب و نمایش داده می‌شوند. فایل‌های زیر نیز ذخیره می‌گردند:
- `clean_ips.txt` — نتایج کامل با جزئیات (تأخیر، packet loss، سرعت دانلود، سرعت آپلود)
- `clean_ips_list.txt` — لیست ساده‌ی IP‌ها

پس از ذخیره‌ی موفق هر دو فایل، ابزار آن‌ها را به‌طور خودکار در پوشه‌ی Downloads اندروید هم کپی می‌کند (بخش بعد را ببینید).

در اسکن چندپورتی، جدول ترمینال یک ستون `Port` دارد و در هر دو فایل، هر خط به‌صورت `IP:Port` نوشته می‌شود (برای IPv6 به شکل `[IPv6]:Port`)، مثلاً:

```
104.16.123.45:443
104.16.123.45:2053
188.114.97.163:8443
```

### کپی خودکار نتایج در Downloads اندروید

بعد از هر اسکن که هر دو فایل نتایج با موفقیت ساخته شوند، ابزار آن‌ها را در مسیر زیر کپی می‌کند (پوشه‌ی Download گوشی):

```
~/storage/downloads/clean_ips.txt
~/storage/downloads/clean_ips_list.txt
```

- در هر دو حالت Normal و Xray کار می‌کند، و اگر اسکن را با Ctrl+C متوقف کنید ولی نتایجی ذخیره شده باشد، آن‌ها هم کپی می‌شوند
- فایل‌های قبلی در Downloads با نتایج جدید **جایگزین** می‌شوند (نتایج جدید به قبلی‌ها اضافه نمی‌شوند)
- محتوای فایل‌های کپی‌شده دقیقاً همان فایل‌های اصلی است و فایل‌های اصلی در پوشه‌ی ابزار دست‌نخورده می‌مانند
- اگر اسکن نتیجه‌ای نداشته باشد، چیزی کپی نمی‌شود و فایل‌های قدیمی هرگز به‌جای نتایج جدید کپی نمی‌شوند

**اولین بار (دسترسی به حافظه):**

اگر Termux هنوز به حافظه‌ی مشترک اندروید دسترسی نداشته باشد، ابزار خودش دستور `termux-setup-storage` را اجرا می‌کند. این کار ممکن است دو مرحله‌ی جداگانه داشته باشد:

1. **تأیید داخل Termux (فقط اگر پوشه‌ی `~/storage` از قبل وجود داشته باشد):** ابزار قبل از اجرا توضیح می‌دهد که Termux ممکن است این سؤال را بپرسد:

```
Do you want to continue? (y/n)
```

حرف `y` را تایپ کنید و Enter بزنید. این مرحله فقط ساختار لینک‌های حافظه‌ی Termux را دوباره می‌سازد و به فایل‌های واقعی گوشی شما، از جمله فایل‌های داخل Downloads، آسیبی نمی‌زند. اگر `n` بزنید، کپی خودکار لغو می‌شود، فایل‌های اصلی در پوشه‌ی ابزار سالم می‌مانند و بدون انتظار اضافه پیام راهنما نمایش داده می‌شود.

2. **درخواست دسترسی اندروید:** اندروید یک پنجره‌ی جداگانه برای دسترسی به حافظه نمایش می‌دهد و **باید شما روی Allow بزنید** — هیچ برنامه‌ای نمی‌تواند این دسترسی را بدون تأیید شما بگیرد. تایپ `y` در Termux به‌معنی دادن دسترسی اندروید نیست.

ابزار تا ۶۰ ثانیه منتظر تأیید می‌ماند و بعد از آن هر دو فایل را کپی می‌کند. این کار فقط یک‌بار لازم است؛ در اسکن‌های بعدی که Downloads در دسترس باشد، `termux-setup-storage` اجرا نمی‌شود و هیچ سؤالی پرسیده نمی‌شود.

اگر دسترسی را تأیید نکنید یا مشکلی پیش بیاید، اسکن خراب نمی‌شود و فایل‌های اصلی سر جای خود می‌مانند. ابزار دلیل مشکل و راه‌حل را نمایش می‌دهد:
1. دستور `termux-setup-storage` را اجرا کنید، اگر پرسید `Do you want to continue? (y/n)` حرف `y` را بزنید و Enter کنید، سپس Allow را بزنید. اگر پنجره‌ای نمایش داده نشد، از تنظیمات اندروید به مسیر Apps ← Termux ← Permissions بروید و دسترسی Files یا Storage را فعال کنید
2. اسکن بعدی نتایج را خودکار کپی می‌کند؛ برای کپی فوری نتایج همین اسکن می‌توانید این دستور را در پوشه‌ی ابزار اجرا کنید:

```bash
cp clean_ips.txt clean_ips_list.txt ~/storage/downloads/
```

## 📋 تغییر لیست IP‌های اسکن (پشتیبانی از تمام CDN‌ها)

> **قابلیت مهم:** این ابزار محدود به Cloudflare نیست. با تغییر فایل `ip_ranges.txt` می‌توانید IP‌های هر CDN دیگری را اسکن کنید.

ابزار به‌صورت پیش‌فرض از رنج‌های رسمی **Cloudflare** استفاده می‌کند. اما شما می‌توانید رنج IP‌های هر CDN زیر را جایگزین کنید یا به لیست اضافه کنید:

| CDN | توضیح |
|-----|-------|
| **Cloudflare** | پیش‌فرض ابزار — رنج‌های رسمی از cloudflare.com/ips |
| **Akamai** | یکی از بزرگ‌ترین CDN‌های جهان |
| **Fastly** | CDN محبوب سرویس‌های بزرگ |
| **Amazon CloudFront** | CDN آمازون AWS |
| **Microsoft Azure CDN** | CDN مایکروسافت |
| **Google Cloud CDN** | CDN گوگل |
| **BunnyCDN** | CDN اروپایی با قیمت مناسب |
| **KeyCDN** | CDN سوئیسی |
| **Limelight Networks** | CDN برای استریمینگ |

> **نکته‌ی بسیار مهم برای حالت Xray:** اگر IP‌های یک CDN خاص را در `ip_ranges.txt` قرار دادید، کانفیگ Xray شما **حتماً باید روی همان CDN** تنظیم شده باشد. یعنی اگر IP‌های Akamai را اسکن می‌کنید، سرور پروکسی شما باید روی Akamai باشد — نه Cloudflare یا CDN دیگری. در غیر این صورت هیچ IP سالمی پیدا نخواهد شد.

### پیدا کردن فایل ip_ranges

```bash
# روش اول (دانلود مستقیم):
nano config/ip_ranges.txt

# روش دوم (ساخت از سورس):
nano ~/Clean-IP-Scanner/config/ip_ranges.txt
```

### فرمت فایل

هر خط می‌تواند شامل یک IP منفرد یا یک رنج CIDR باشد:

```
103.21.244.0/22
103.22.200.0/22
104.16.0.0/13
188.114.96.0/20
190.93.240.0/20
197.234.240.0/22
198.41.128.0/17
```

**نکته:** ابزار رنج‌های CIDR را به‌طور خودکار گسترش می‌دهد، IP‌های تکراری را حذف می‌کند، و قبل از شروع اسکن ترتیب تمام IP‌ها را به‌صورت کاملاً تصادفی درمی‌آورد.

### محدودیت‌های اسکن — IPv4 و IPv6

**برای IPv4:** هیچ محدودیت عملی وجود ندارد. می‌توانید ده‌ها میلیون IP در فایل داشته باشید. تمام رنج‌های استاندارد CDN‌ها مثل `/22`، `/20`، `/16`، حتی `/13` (حدود ۵۰۰ هزار IP) بدون هیچ مشکلی اسکن می‌شوند. تنها اگر **یک خط منفرد** بیش از ۵ میلیون IP داشته باشد (مثلاً `/8` = 16 میلیون IP) آن خط رد می‌شود — اما بقیه‌ی رنج‌ها به‌طور عادی اسکن می‌شوند. در عمل رنج‌های IPv4 CDN‌ها هرگز این حد را ندارند.

**برای IPv6:** مشکل اینجاست که رنج‌های استاندارد CDN‌ها در IPv6 معمولاً `/32` هستند که هر کدام میلیاردها آدرس دارند — اسکن یک‌به‌یک آن‌ها غیرممکن است. ابزار این رنج‌ها را رد می‌کند و پیام راهنما نمایش می‌دهد. برای IPv6 از subnet‌های بسیار کوچک استفاده کنید:

```
# اشتباه — خیلی بزرگ، رد می‌شود:
2606:4700::/32

# درست — قابل اسکن:
2606:4700::/120
2606:4700:10::/120
2606:4700:20::/120
```

یک `/120` در IPv6 فقط ۲۵۶ آدرس دارد و کاملاً قابل اسکن است.

## ⚙️ تنظیم کانفیگ برای حالت Xray (راهنمای کامل)

> **توضیح مهم:** در حالت Xray، شما یک کانفیگ شخصی تعریف می‌کنید. ابزار IP‌های مختلف را در آن کانفیگ قرار می‌دهد و تست می‌کند که کدام IP با کانفیگ شما کار می‌کند. بنابراین کانفیگی که تعریف می‌کنید باید از نظر UUID، سرور، و تنظیمات معتبر باشد — تنها چیزی که ممکن است مسدود شده باشد IP آن است.

> **هم‌خوانی کانفیگ با CDN انتخابی:** کانفیگ Xray شما باید با CDN‌ای که IP‌های آن را در `ip_ranges.txt` قرار داده‌اید **هم‌خوانی داشته باشد**. برای مثال:
> - اگر رنج IP‌های **Cloudflare** را اسکن می‌کنید ← کانفیگ شما باید روی سرور Cloudflare تنظیم شده باشد
> - اگر رنج IP‌های **Akamai** را اسکن می‌کنید ← کانفیگ شما باید روی سرور Akamai تنظیم شده باشد
> - اگر رنج IP‌های **Fastly** را اسکن می‌کنید ← کانفیگ شما باید روی سرور Fastly تنظیم شده باشد
>
> **CDN کانفیگ و CDN فایل ip_ranges.txt باید یکی باشند، در غیر این صورت هیچ IP سالمی پیدا نخواهد شد.**

ساده‌ترین روش، وارد کردن کانفیگ به‌صورت تعاملی داخل خود ابزار است: بعد از انتخاب گزینه ۲ (Xray)، فرمت URL یا JSON را انتخاب کنید و کانفیگ را Paste کنید (جزئیات در بخش «وارد کردن کانفیگ Xray» بالا). کانفیگ بررسی و به‌صورت خودکار ذخیره می‌شود و دفعه‌ی بعد نیازی به وارد کردن مجدد نیست.

اگر ترجیح می‌دهید فایل‌ها را خودتان ویرایش کنید، روش‌های دستی زیر همچنان کار می‌کنند. در این حالت باید **یکی** از دو فایل زیر را ویرایش کنید.

---

### ویرایش دستی: فرمت URL (ساده‌تر)

```bash
nano config/xray_config.txt
```

لینک کانفیگ خود را در فایل قرار دهید:

```
vless://9b8928b1-5394-4433-bf94-6116fd5656b3@example.com:443?type=ws&security=tls&host=example.com&path=%2Fproxy&sni=example.com#MyConfig
```

> خطوطی که با `#` شروع می‌شوند به‌عنوان توضیح نادیده گرفته می‌شوند.

> **یادآوری:** مطمئن شوید این کانفیگ متعلق به همان CDN‌ای است که IP‌های آن را در `ip_ranges.txt` قرار داده‌اید.

**ذخیره و خروج از nano:** `Ctrl+O` → Enter → `Ctrl+X`

**پروتکل‌های پشتیبانی‌شده:** `vless://` · `vmess://` · `trojan://` · `ss://`

---

```bash
nano config/xray_config.json
```

**نمونه کانفیگ JSON:**

```json
{
  "log": { "loglevel": "warning" },
  "inbounds": [
    {
      "port": 1080,
      "protocol": "socks",
      "settings": { "udp": false },
      "listen": "127.0.0.1"
    }
  ],
  "outbounds": [
    {
      "protocol": "vless",
      "settings": {
        "vnext": [
          {
            "address": "your-server-ip-or-domain",
            "port": 443,

              {
                "id": "your-uuid-here",

              }
            ]
          }
        ]

        "security": "tls",
```

> **نکته:** اگر هر دو فایل پر باشند و کانفیگی را از طریق منوی تعاملی ذخیره نکرده باشید، فایل `xray_config.txt` (فرمت URL) اولویت دارد. هر بار که کانفیگی را از طریق منوی تعاملی ذخیره کنید، همان فرمت برای اسکن انتخاب می‌شود (حتی اگر فایل فرمت دیگر هم پر باشد) و این انتخاب در فایل `config/xray_config.active` نگهداری می‌شود. اگر بعد از آن فایل فرمت دیگر را دستی پر کرده‌اید و می‌خواهید از آن استفاده شود، در منوی تعاملی گزینه‌ی Edit را بزنید یا فایل `config/xray_config.active` را حذف کنید تا قانون اولویت URL دوباره اعمال شود.

> **یادآوری:** مطمئن شوید این کانفیگ متعلق به همان CDN‌ای است که IP‌های آن را در `ip_ranges.txt` قرار داده‌اید.

## ❓ سوالات متداول

**آیا این ابزار فقط برای Cloudflare است؟**

خیر. با تغییر فایل `config/ip_ranges.txt` می‌توانید IP‌های هر CDN دیگری مانند Akamai، Fastly، Amazon CloudFront، Microsoft Azure CDN، Google Cloud CDN و غیره را اسکن کنید.

**چه تعداد IP می‌توانم در لیست داشته باشم؟**

برای **IPv4** عملاً هیچ محدودیتی وجود ندارد — می‌توانید ده‌ها میلیون IP در فایل داشته باشید. تمام رنج‌های استاندارد CDN‌ها (مثل `/22`، `/20`، `/16`، `/13`) بدون مشکل کار می‌کنند.

برای **IPv6** باید از subnet‌های کوچک استفاده کنید. رنج‌های بزرگ مثل `/32` میلیاردها آدرس دارند که اسکن یک‌به‌یک آن‌ها غیرممکن است. از `/120` یا کوچک‌تر استفاده کنید.

**آیا IPv6 هم پشتیبانی می‌شود؟**

بله، با شرط استفاده از subnet‌های کوچک. یک `/120` فقط ۲۵۶ آدرس دارد و کاملاً قابل اسکن است. اگر رنجی خیلی بزرگ باشد، ابزار به جای crash آن خط را رد کرده و پیام راهنما نمایش می‌دهد.

**آیا برای حالت Xray باید فایل کانفیگ را با nano ویرایش کنم؟**

خیر. بعد از انتخاب گزینه ۲، کانفیگ خود را (URL یا JSON) مستقیماً در ترمینال Paste کنید؛ ابزار آن را بررسی و ذخیره می‌کند. برای JSON چندخطی، بعد از Paste کردن، در یک خط جداگانه `END` را تایپ کنید. ویرایش دستی فایل‌ها هم همچنان ممکن است.

**چطور کانفیگ Xray ذخیره‌شده را عوض کنم؟**

اسکن Xray را شروع کنید. وقتی ابزار کانفیگ ذخیره‌شده را تشخیص داد و پرسید، گزینه‌ی `[2] Edit configuration` را انتخاب کنید و کانفیگ جدید را وارد کنید.

**نتایج در کدام پوشه‌ی گوشی کپی می‌شوند؟**

در پوشه‌ی Download (Downloads) گوشی، یعنی مسیر `~/storage/downloads/` در Termux. فایل‌های `clean_ips.txt` و `clean_ips_list.txt` بعد از هر اسکن جایگزین نسخه‌ی قبلی می‌شوند.

**چرا اندروید درخواست دسترسی نشان می‌دهد؟**

برای کپی نتایج در Downloads، Termux به حافظه‌ی مشترک اندروید نیاز دارد. ابزار در اولین اسکن خودش `termux-setup-storage` را اجرا می‌کند و شما فقط باید یک‌بار روی Allow بزنید. بعد از آن نیازی به تأیید مجدد نیست.

**تعداد worker چه عددی وارد کنم؟**

- دستگاه‌های قدیمی یا ضعیف: ۴
- اکثر دستگاه‌های معمولی: ۸ (پیش‌فرض)
- دستگاه‌های قوی: ۱۶

اگر مطمئن نیستید، Enter بزنید تا عدد پیش‌فرض ۸ استفاده شود.

**چه پورتی برای اسکن وارد کنم؟**

بستگی به کانفیگ شما دارد. در اکثر موارد پورت **۴۴۳** (پیش‌فرض) مناسب است. اما اگر سرور شما روی پورت دیگری مثل ۸۰، ۲۰۵۳، یا ۲۰۸۳ کار می‌کند، می‌توانید همان پورت را وارد کنید تا اسکن دقیق‌تری داشته باشید. اگر می‌خواهید بدانید هر IP روی کدام پورت‌ها سالم است، می‌توانید تا ۱۳ پورت را با کاما جدا کرده و همزمان وارد کنید. اگر مطمئن نیستید، Enter بزنید تا پورت پیش‌فرض ۴۴۳ استفاده شود.

**اگر اسکن قطع شود چه اتفاقی می‌افتد؟**

پیشرفت ذخیره می‌ماند. دفعه‌ی بعد که ابزار را اجرا کنید، اسکن ناتمام را تشخیص داده و می‌پرسد آیا می‌خواهید ادامه دهید یا از نو شروع کنید. پورت‌های انتخابی قبلی نیز به‌صورت خودکار بازیابی می‌شوند.

**آیا می‌توان یک لیست بسیار بزرگ را در چند روز اسکن کرد؟**

بله، کاملاً ممکن است. می‌توانید هر روز چند صد هزار یا چند میلیون IP اسکن کنید و هربار از همان‌جایی که متوقف شده‌اید ادامه دهید. ابزار تضمین می‌کند هیچ IP قبلاً اسکن‌شده‌ای تکرار نشود.

**چرا IP پیدا نمی‌کند؟**

- در ساعات کم‌ترافیک دوباره امتحان کنید
- مطمئن شوید هیچ VPN فعالی ندارید
- از حالت Xray با یک کانفیگ معتبر استفاده کنید
- در حالت Xray، مطمئن شوید کانفیگ شما متعلق به همان CDN‌ای است که IP‌های آن را اسکن می‌کنید
- پورت (یا پورت‌های) وارد شده را با پورت کانفیگ خود مقایسه کنید

**IP‌ها بر چه اساسی مرتب می‌شوند؟**

بر اساس مجموع سرعت دانلود و سرعت آپلود. IP‌ای که هم دانلود و هم آپلود خوبی داشته باشد در رتبه‌ی بالاتری نسبت به IP‌ای قرار می‌گیرد که فقط در یکی از این دو قوی است.

**چقدر طول می‌کشد؟**

- **حالت Normal:** مرحله‌ی تأخیر ۲ تا ۳ دقیقه، مرحله‌ی سرعت (دانلود + آپلود) ۲ تا ۴ دقیقه
- **حالت Xray:** بستگی به تعداد worker و سرعت دستگاه دارد. با ۸ worker حدود ۹ تا ۱۷ دقیقه (شامل تست دانلود و آپلود)

## 🔧 عیب‌یابی

**خطا: `Permission denied`**
```bash
chmod +x clean-ip-scanner
```

**خطا: `wget not found` یا `curl not found`**
```bash
pkg install wget curl unzip
```

**خطا: `Xray binary not found`**

دوباره از مراحل نصب شروع کنید.

**پیام: `No valid Xray configuration was found`**

این پیام یعنی هنوز کانفیگ معتبری ذخیره نشده است. طبق راهنمای روی صفحه، فرمت URL یا JSON را انتخاب و کانفیگ را Paste کنید. اگر ترجیح می‌دهید، یکی از این دو فایل را به‌صورت دستی ویرایش کنید:
- `config/xray_config.txt` برای فرمت URL
- `config/xray_config.json` برای فرمت JSON

**پیام: `Storage access was not granted`**

اندروید دسترسی حافظه را به Termux نداده است، بنابراین نتایج در Downloads کپی نشدند (فایل‌های اصلی سالم‌اند). دستور `termux-setup-storage` را اجرا کنید و Allow را بزنید؛ اگر پنجره نمایش داده نشد، از تنظیمات اندروید مسیر Apps ← Termux ← Permissions دسترسی Files یا Storage را فعال کنید و دوباره اسکن کنید.

**خطا: `unsupported protocol`**

پروتکل‌های معتبر: `vless://`، `vmess://`، `trojan://`، `ss://`

**خطا: `no SOCKS inbound found`**

کانفیگ JSON شما فاقد بخش inbound از نوع SOCKS است. بر اساس نمونه‌ی بالا اصلاح کنید.

**پیام: `Skipping 2606:4700::/32 (IPv6 /32): contains ... addresses`**

رنج IPv6 شما خیلی بزرگ است. از `/120` یا کوچک‌تر استفاده کنید. مثال: `2606:4700::/120`

**خطا: `No IPs to scan`**

تمام رنج‌های فایل `ip_ranges.txt` رد شده‌اند. رنج‌های IPv4 اضافه کنید یا subnet IPv6 را کوچک‌تر کنید.

## 💡 نکات مهم

- اسکن را **بدون VPN فعال** انجام دهید تا نتایج دقیق‌تری بگیرید
- فایل `clean_ips.txt` را برای استفاده‌ی بعدی نگه دارید
- کانفیگ Xray را می‌توانید مستقیماً در ترمینال وارد کنید؛ اگر فایل‌ها را دستی ویرایش می‌کنید، فقط **یکی** از دو فایل کانفیگ را پر کنید (در نبود انتخاب از منوی تعاملی، فایل txt اولویت دارد)
- بعد از هر اسکن، نتایج در پوشه‌ی Downloads گوشی هم کپی می‌شوند
- **کانفیگ Xray شما باید با CDN مورد نظر هم‌خوانی داشته باشد**
- **پورت اسکن را با پورت کانفیگ خود هماهنگ کنید** — اگر مطمئن نیستید، Enter بزنید تا پورت پیش‌فرض ۴۴۳ استفاده شود
- در هر لحظه با **Ctrl+C** می‌توانید اسکن را متوقف کنید — پیشرفت ذخیره می‌ماند
- برای IPv6 از subnet‌های `/120` یا کوچک‌تر استفاده کنید
- فایل `scan_checkpoint.json` را دستی پاک نکنید مگر اینکه بخواهید اسکن قبلی را کامل فراموش کنید
